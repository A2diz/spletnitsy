## Правила разработки и проверки изменений

### 🔍 Обязательные проверки при каждом изменении:

#### 1. **Отображение на всех устройствах**
- **Десктоп:** Проверь на ширине 1920px, 1440px, 1200px
- **Планшет:** Проверь на ширине 768px, 1024px
- **Мобильный:** Проверь на ширине 375px, 414px, 360px
- **Особое внимание:** Проверь на iPhone SE (375px), iPad (768px)

#### 2. **Взаимосвязанные элементы**
При изменении любого элемента проверяй и обновляй **ВСЕ связанные места**:

- **Текущая книга:**
  - Название и автор в блоке "Читаем сейчас" (раздел BOOKS)
  - Название и автор в блоке "Встречи" (раздел SCHEDULE)
  - JSON файл `_data/current_book.json`
  - Счетчик книг в заголовке раздела BOOKS
  - Архивные оценки в localStorage

- **Счетчики и статистика:**
  - Общее количество книг в заголовке
  - Количество участников в блоке "Участницы"
  - Рейтинги в таблице книг

- **Навигация:**
  - Все ссылки в меню работают
  - Якорные ссылки ведут к правильным секциям
  - Мобильное меню корректно открывается/закрывается

#### 3. **Функциональность**
- **Формы:** Все поля валидируются, кнопки работают
- **JavaScript:** Нет ошибок в консоли, все функции выполняются
- **localStorage:** Данные сохраняются и загружаются корректно
- **API/JSON:** Все запросы обрабатываются с fallback'ами

#### 4. **Smoke-test деплоя: GitHub Pages + Netlify**
После любого изменения в `index.html`, `_data/*.json` или `netlify/functions/*` обязательно проверить:
- `https://a2diz.github.io/spletnitsy/` и `https://bkspletnitsy.netlify.app/` отображают одинаково важные секции: hero, books, rating block, participants, schedule, gallery, join form
- на GitHub Pages `/_data/current_book.json` и `/_data/ratings.json` отдают `200`
- `https://bkspletnitsy.netlify.app/.netlify/functions/ratings` отвечает `ok: true`
- preflight/CORS для Netlify-функций не ломается после деплоя
- тестовая оценка ставится, сохраняется после обновления страницы и видна всем
- в консоли нет `ReferenceError`, `Cannot access before initialization` и других ошибок первого рендера
- битый или старый `localStorage` не должен ломать страницу: данные нужно безопасно игнорировать или сбрасывать
- не вызывать `render*()` или другие функции до инициализации всех зависимых переменных
- не использовать жёсткие root-relative пути вроде `/admin/...` или `/.netlify/...` без `SITE_BASE` или полного абсолютного URL

#### 5. **Визуальная консистентность**
- **Цвета:** Используй только переменные CSS (`--rose`, `--ink` и т.д.)
- **Шрифты:** Только подключенные шрифты (Playfair Display, DM Sans)
- **Отступы:** Следуй существующей сетке (rem, em)
- **Анимации:** Плавные переходы без лагов

#### 5. **Специфические правила проекта**

##### Добавление новой книги:
1. Обнови `_data/current_book.json` (title, author, meeting_date)
2. Проверь что старая книга архивирована в localStorage
3. При переводе книги в прочитанные добавь запись в `BOOK_ARCHIVE_LOG.md` с датой, названием, автором и статусом по рейтингу
4. Обнови счетчик книг в заголовке раздела BOOKS
5. Очисти форму оценок для новой книги
6. Проверь отображение на всех устройствах

##### Добавление участницы:
1. Добавь в массив `participants` в JavaScript
2. Проверь что фото загружено на GitHub
3. Обнови URL фото в коде
4. Проверь адаптивность сетки участниц

##### Изменение рейтинга:
1. Проверь что оценки сохраняются в localStorage
2. Проверь архивацию при смене книги
3. Проверь отображение в таблице книг
4. Проверь мобильную версию списка голосов

## Стек проекта

- **Основной язык:** HTML, CSS, JavaScript (vanilla)
- **В будущем возможно:** добавление других технологий (обновляй этот раздел при изменениях)

---

## При ревью Pull Request проверяй:

### HTML
- Валидная семантическая разметка (используй `<header>`, `<main>`, `<section>`, `<article>` и т.д.)
- Наличие `alt` у всех `<img>`
- Наличие `lang` атрибута у `<html>`
- Правильная структура заголовков (h1 → h2 → h3, без пропусков)
- Мета-теги: `charset`, `viewport`, `description`, `title`

### CSS
- Нет инлайн-стилей (`style="..."`) — только классы
- Нет !important без крайней необходимости
- Адаптивность: проверь наличие media queries для мобильных
- Переменные CSS (`--var`) для цветов и отступов

### JavaScript
- Нет `console.log` в продакшн-коде
- Обработка ошибок в fetch/async операциях
- Нет глобальных переменных без необходимости

### Безопасность
- Нет хардкода ключей, паролей, токенов
- XSS: нет `innerHTML` с пользовательскими данными без санитизации

### Производительность
- Изображения оптимизированы (предпочитать WebP/SVG)
- Внешние шрифты подключены через `preconnect`
- JS-скрипты с `defer` или `async`

## При создании файлов и кода:

- Следуй существующей структуре папок проекта
- Создавай новые HTML-страницы с полным базовым шаблоном (DOCTYPE, head, meta, title)
- Добавляй комментарии к сложным блокам CSS/JS
- После создания файлов — всегда открывай Pull Request, не коммить напрямую в main/master
- В описании PR кратко опиши: что создано, зачем, что проверить

---

## При генерации тестов:

- Проверяй наличие ключевых HTML-элементов
- Тестируй доступность (aria-labels, роли)
- Для JS-функций пиши unit-тесты
